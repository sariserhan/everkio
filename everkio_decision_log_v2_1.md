## Specification elaborations in this revision
The following are newly specified evaluation protocols, not previously confirmed customer outcomes or measured performance. They are explicit v2.1 criteria; freeze them before testing and record any requested change before evaluation.

| ID | Elaboration | Rationale / effect |
|---|---|---|
| E01 | Presence: three ≥10-minute sessions per animal/device, p95 frame time ≤33.3 ms, sustained one-minute ≥30 FPS, ≥100 touch samples and p95 <100 ms | Makes the retained 30 FPS/latency requirements reproducible; retains 60 FPS as aspirational. |
| E02 | Presence: ≥20 blinded evaluators, ≥80% ratings ≥4/5 for each species/dimension; zero major motion/contact defects | Converts “strong qualitative realism” into a scored protocol without claiming it has passed. |
| E03 | Identity: ≥20 distinct pets per intended path, ≥10 of each species, ≥90% acceptance per path and species, held-out/full-motion checks, confidence intervals | Replaces v2.0's candidate 20-total/90% target with explicit path-specific evidence; failed/abstained eligible cases count. |
| E04 | Memorial: ≥10 consenting adults; ≥90% comprehension and task success per measure; zero unresolved critical defects | Adds a separate measurable memorial UX gate; prototype evidence alone cannot pass production privacy/deletion requirements. |
| E05 | One initial reconstruction plus at most one bounded correction per pet; two unsuccessful rounds stop the path | Bounds research and correction exposure without inventing a spending authorization. |
| E06 | Numerical research funding, caps and commercial margin floor remain UNSET | Avoids fabricated budget approval. Missing funding blocks billable experiments; unknown economics blocks commercial viability. |
| E07 | Every gate starts NOT RUN; blocker ownership and evidence fields are mandatory | Separates documented plans from actual feasibility, implementation and launch evidence. |
| E08 | External platform references retained but explicitly not reverified | This documentation task does not assert current SDK/licensing availability; verification is an execution prerequisite. |
